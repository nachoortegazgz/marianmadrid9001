# Dossier técnico CMS — colecciones personalizadas

> **Criterio de identificación**
>
> - **ID técnico:** identificador interno real de Wix.
> - **ID público:** nombre público en español, `camelCase`, sin espacios y respetando el orden semántico del ID técnico.
> - **Tipo de dato:** tipo CMS.
> - **Protección:** permisos, cifrado o condición especial.
>
> # Directrices de nomenclatura utilizadas

## 1. Colecciones

| Elemento | Directriz | Ejemplo |
|---|---|---|
| ID técnico | Se conserva exactamente el ID real de Wix | `DatosFiscales` |
| ID público | Nombre visible de la colección | `DATOS_FISCALES` |
| Tipo | Colección nativa CMS personalizada | `Nativa` |
| Apps Wix | Se excluyen del inventario personalizado | `Bookings/Services` |

---

## 2. Campos

Cada campo se documenta con cuatro valores:

```text
ID técnico | ID público | Tipo de dato | Protección
```

### Reglas del ID técnico

- No se modifica.
- Se conserva la clave real de Wix.
- Respeta mayúsculas y minúsculas originales.
- Ejemplo: `businessTaxId`.

### Reglas del ID público

El nombre público:

1. Está en español.
2. Usa `camelCase`.
3. Empieza en minúscula.
4. No contiene espacios.
5. No utiliza guiones ni guiones bajos.
6. Mantiene el orden de términos del ID técnico.
7. Traduce los términos sin invertirlos.
8. Conserva siglas reconocibles cuando corresponde.
9. Mantiene nombres técnicos establecidos como `sku`, `qr`, `sii` o `verifactu`.

## 4. Ejemplos incorrectos

| Incorrecto | Correcto | Motivo |
|---|---|---|
| `nombreNegocio` | `negocioNombre` | Invierte el orden original |
| `ubicación` | `localizacion` | Lleva acento y no es `camelCase` técnico |
| `localizacion` como ID técnico | `location` | El ID técnico de Wix no se modifica |
| `NombreNegocio` | `negocioNombre` | Empieza con mayúscula |
| `negocio_nombre` | `negocioNombre` | Contiene guion bajo |
| `NIF/CIF AEAT` | `negocioIdentificacionFiscal` | Contiene espacios y formato no técnico |
| `SERVICIOS_CATALOGO` como campo | `serviciosCatalogo` | El campo público debe ser `camelCase` |

## 6. Tipos de datos

Los tipos se mantienen exactamente como los define Wix:

```text
TEXT
NUMBER
BOOLEAN
DATE
DATETIME
IMAGE
RICH_TEXT
OBJECT
ARRAY_STRING
REFERENCE
MULTI_REFERENCE
```

No se traducen los valores del tipo de dato.

---

## 7. Protección

La columna de protección documenta:

```text
ADMIN
SITE_MEMBER
SITE_MEMBER_AUTHOR
ANYONE
Cifrado
Sistema Wix
Requerido
```

Ejemplos:

| Campo | Protección |
|---|---|
| `businessTaxId` | `ADMIN / cifrado` |
| `businessName` | `ADMIN / requerido` |
| `location` en `ComplementosCatalogo` | `ANYONE` |
| `_id` | `Sistema Wix` |

---

## 8. Regla especial para referencias

Los campos `REFERENCE` y `MULTI_REFERENCE` conservan:

- El ID técnico original.
- El tipo Wix original.
- La colección de destino.
- El orden de términos en el ID público.

Ejemplo:

```text
location
→ localizacion
→ REFERENCE
```

```text
ServiciosCatalogo_opcionesComplementos
→ serviciosCatalogoOpcionesComplementos
→ MULTI_REFERENCE
```

---

## 9. Regla de seguridad

La nomenclatura pública no debe alterar:

- El funcionamiento del código.
- Las relaciones CMS.
- Los IDs técnicos.
- Los nombres de campos utilizados por Velo.
- Los tipos de datos.
- Los metadatos de referencias.

La traducción afecta únicamente al `displayName` del campo, no a su `key` técnico.

# 5. Seguridad y predespliegue

- Las colecciones fiscales, contables, de caja, inventario y personal están restringidas a `ADMIN`.
- `DatosFiscales.businessTaxId` está cifrado.
- `ComplementosCatalogo` mantiene lectura `ANYONE`; debe revisarse la exposición de campos internos.
- `RegistrosHorariosStaff` contiene IP, identificadores laborales y datos personales.
- `DatosFiscales` y `ConfiguracionFiscal` tienen campos solapados; debe definirse una única fuente fiscal.
- `ServiciosCatalogo.taxRate` es `TEXT`; si participa en cálculos debe normalizarse a `NUMBER`.
- Los importes de `ProveedoresLista` están definidos como `TEXT`.
- Las cachés, colas y bloqueos deben limpiarse al expirar.
- Las referencias `REFERENCE` y `MULTI_REFERENCE` deben conservar sus metadatos nativos.

## Dictamen

La estructura queda documentada con los IDs técnicos actuales y los IDs públicos corregidos. En todos los campos de ubicación se aplica:

```text
location      → localizacion
locationId    → localizacionId
```

Los campos técnicos no se modifican; solo se normalizan sus nombres públicos.
